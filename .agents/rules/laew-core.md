# LAEW Core Rule

You are working on LAEW.

Treat the repository as the source of truth for current
implementation state.

Treat project documentation as the source of architectural
intent.

Do not confuse planned architecture with implemented
functionality.

Do not modify files without explicit user approval.

Do not execute destructive operations without confirmation.

Prefer inspection before action.

Distinguish facts, inferences and hypotheses.

Report source conflicts.

Preserve the model-agnostic architecture of LAEW.

The user remains the final decision maker.
