# BW-07 isolated fixture operations

Use disposable source trees and operator media. The production worker 0.1.0 and its existing profile remain in supervised mode. Only the candidate worker 0.2.0 understands these commands. Invocations below use the installed candidate's absolute Python with `-I -B -m laew.backup_worker`.

## Policy and Workbench

1. Use a private absolute profile, archive directory and operator context. Use `control initialize --profile PROFILE --apply` to provision a disabled policy, or add `--managed` for the Debian managed fixture. The policy is bound to the profile bytes. Provision it while no old backup command is running. Older 0.1.0 workers do not consult this policy and must be excluded from a managed media boundary before enabling it.
2. Inspect `control view --profile PROFILE`. Publish an owner-protected projection with `control publish-view --profile PROFILE --output ABSOLUTE/backup-settings.json --apply`. The projection requires a separate directory disjoint from private and source paths. Pass `--status-file` to include validated local worker health and `--transport` to include the enrolled key label. If the reader uses a different account, provision traversal and read-only group/ACL access to this directory and file. On Debian use a setgid reader directory. Point isolated Core at the exact projection and owner with `LAEW_BACKUP_WORKBENCH_VIEW` and `LAEW_BACKUP_WORKBENCH_OWNER`. Windows production keeps both unset until the SID boundary qualifies.
3. Workbench downloads a draft for folder validation, settings change, or connection test. Review it with the operator and use `control validate-directory|apply|test-connection --profile PROFILE --proposal DRAFT --apply`, optionally adding `--transport` for reviewed SFTP settings. A different directory requires an independently reviewed new profile and provenance before activation. The validate action only inspects the selected destination and capacity. Publish a fresh view after approved actions.
4. `control disable --profile PROFILE --apply` blocks new managed captures, replication and connection tests without deleting generations. A previously admitted operation runs to its terminal boundary. The view can report `disabling` until it releases its lock. Read-only verification and separately approved isolated restores remain available.

The status and settings channels require protected ancestors up to the filesystem root. Windows currently accepts only the worker owner, LocalSystem and Administrators as ancestor owners and rejects third-party ACL grants beyond read or execute. Ordinary Windows paths can fail this conservative check. Keep the channels off until the exact paths and identity boundary qualify.

## Debian managed capture

Use a dedicated test host or VM with a real systemd and cgroup v2. The root-owned controller config and journal live on a protected local filesystem, with no writer-replaceable ancestors. The journal directory is setgid with a dedicated group permitted to read and traverse. Both the non-login writer UID and the separate non-root worker UID require read access to the journal and read/write access to the existing fixed fence file. They require no write or replacement access to the gate directory. The controller directory needs its own precreated `installation.lock`, separate from the writer fence.

Controller config is JSON with `schema_version`, absolute `profile`, `writer_services`, `worker_service` and `unit_sha256`. The last field maps each exact unit name to the SHA-256 of its `systemctl cat` output. Review the effective units, drop-ins and real account boundaries offline. Pin the final reviewed files. Use non-root writer and worker accounts. Writer units need the three explicit enrollment environment variables `LAEW_INSTALLATION_FENCE`, `LAEW_MANAGED_WRITER_GATE` and `LAEW_MANAGED_WRITER_UNIT`. Each writer entrypoint must call the existing enrollment before any source write and acknowledge a graceful drain with exit zero. The one-shot worker uses `managed-create --profile PROFILE --gate GATE --provenance RELEASE --apply`. Disable service auto-restart and activation on the fixture. Test attempts to bypass the gate from direct entrypoints, other UID contexts, shell, synchronization and alternate launch mechanisms.

With all reviewed units inactive, the protected system operator invokes the candidate interpreter with `-I -B -m laew.backup.controller initialize --config CONFIG`. In the fixture, `capture` latches the journal and drains the pinned writer set, starts the pinned one-shot worker and independently verifies the exact committed receipt before normal resume. On an ambiguous failure, the durable gate holds. `recover` is explicit and checks that the worker is terminal before resuming originally active units. Qualify the cgroup, shutdown result, child lifetime, stale boot ID and native permission boundary before trusting this on operational media. Windows unattended remains a target and requires a separately qualified service adapter and exclusion of unmanaged desktop writers.

## SFTP fixture

Provision the selected server offline under a dedicated account limited to SFTP and one directory. Install the server's host pin under the trusted worker account after out-of-band verification. Expose a public identity from a dedicated OS-protected non-root worker OpenSSH agent. Keep `sftp.json` in the private policy directory. Its v1 fields are `schema_version`, `host`, `port`, `user`, `remote_directory`, `agent`, `known_hosts`, `known_hosts_sha256`, `public_identity`, `public_identity_sha256` and `hardlink_qualified`. The protected operator approves the file and pins. Core only receives a label. Native Windows agent trust is still fail-closed.

With the local policy enabled in a fixture, `control test-connection` validates the approved SSH trust and directory without uploading. `control replicate --profile PROFILE --transport CONFIG --id ID --release-record RELEASE_RECORD --apply` independently verifies the exact local ZIP, receipt and release linkage before transfer. It requires a qualified no-clobber server primitive, reads back staged and final bytes, and publishes the commit marker last. Server staging/probe files remain in failure or success cases. Size the fixture allocation and assign a server operator to manage these artifacts separately. No retention or deletion is part of this command. Remote transfer verification does not replace a representative off-host recovery drill or establish server persistence across power loss.
