## Proposed architecture

### Local run telemetry

Use stdlib logging with a dedicated `laew.telemetry` logger configured via [logging_config.py](../../laew/logging_config.py). Its allowlisted records go to an operator-only telemetry directory per runtime installation, with one uniquely created UTF-8 JSONL file per run. Directory and file ownership and permissions must be checked on Windows and Debian. Avoid shared multi-process rotating file handlers. Keep the general application stderr handler and existing Workbench diagnostics. Sanitize legacy structured tool logs before declaring any diagnostic output shareable. Preserve tool operation, argument shape, outcome code and duration as required by ADR-016. Record the review of its argument/result wording in P01.

- **Envelope v1:** `schema_version`, UTC `ts`, `event`, server-generated UUID `run_id`, increasing `seq`, coarse `surface`, `scope_kind`, opaque `scope_ref` (keyed pseudonym where local lookup requires it), `span_id`, optional `parent_span_id`, `duration_ms` from a monotonic clock, `status`, `error_code` and event-specific fields. Do not use client-provided run or tool IDs as filenames. Workbench may keep its existing scoped IDs for UI and cancellation and hold the telemetry UUID in server-owned run context. Exclude raw project identifiers and names from exported summaries.
- **Lifecycle:** `run.started`, `routing.decided`, `agent.started/finished`, `tool.started/finished`, `llm.started/finished`, bounded `runtime.sample`, `run.finished`. Map workflow, coordinator and nested agent work to child spans. A run is one accepted execution entry point or chat turn. Rejection before admission has no task run. Telemetry for standalone LLM/tool diagnostics uses a separate surface, never a fabricated chat conversation. For aborted streams, exceptions and cancellation, publish one terminal result from an outer finalizer. Crash leaves a started run without terminal event; after verifying producer inactivity, the reader reports `interrupted` without rerunning anything. A live lease or process-owned lock distinguishes current activity from interruption.
- **Tool and model usage:** Fixed tool name/operation vocabulary, broker decision, attempts including retries/errors/cancel, result size only where obtainable without serializing contents. Account once per provider attempt. Use existing diagnostics for dispatch timing and actual token counts. Record `usage_source=reported|estimated|unavailable` per count and keep unknown counts null. Summaries distinguish known totals, estimated totals and attempts with missing usage. Do not retry or call a provider for telemetry. Use bounded classifications such as `validation`, `permission_denied`, `timeout`, `dependency_unavailable`, `io_error`, `cancelled`, `internal_error` and `unknown`.
- **Integration:** Create context at [CLI](../../laew/cli.py), [console commands](../../laew/console/commands), and `WorkspaceService.chat/stream_chat` in [web.py](../../laew/web.py); pass explicit observer/context across executor, worker thread, coordinator, and broker paths. Use [KnowledgeTurn](../../laew/knowledge/routing.py) routing flags and executor diagnostic callbacks through a typed adapter that copies only safe scalar fields. Ensure agent retry instrumentation and low-level tool instrumentation cannot generate duplicate logical spans. Instrument Workbench Cloud Chat and memory/curation worker provider use at their owning wrappers with separate surface/operation types. Do not connect Cloud Chat to local tools, knowledge or memory. Capture exposed RAG/sync outcomes and freshness without instrumenting raw documents or vector payloads.
- **Isolation:** Operator-only local CLI on the owning OS account. Filter by intended scope before resolving any conversation-linked diagnostics. No project-facing API or tool access to telemetry or backup roots. Guard storage against configured aliases or workspace/knowledge roots overlapping it. Serialize from a type and field allowlist. Disallow prompts, text, tool parameters/results, raw exception messages, citations, source paths, usernames, credentials, endpoint URLs with secrets, and provider request IDs or headers. A summary export is explicitly requested, scrubbed and scoped. Legacy logs and session checkpoints remain private until independently reviewed.
- **Performance and failure:** Synchronous bounded buffered records with start/finish flush, a byte/event ceiling that reserves a terminal record, and explicit drop counts. Process crash can lose buffered tail records. No claim of lossless power-failure tracing. Opening, writing and terminal flushing failures produce a coarse degraded signal without throwing into user work. Document sink-off and disk-full behavior. In normal operation every accepted run has one root start and terminal. If storage is unavailable, surface an operational fault through stderr/status rather than claiming success. Proposed warm fixture overhead: median added time ≤3 ms/run and p95 ≤10 ms/run over 500 paired no-network runs, one warmup batch and three alternating measured batches. Cap 256 KiB/run and 256 MiB/installation initially, with 30-day retention proposed. Quota includes active files and is coordinated with cleanup via short locks and bounded admission/caps. Document drop/truncation limits under extreme concurrency.

Retained telemetry is opt-in under D2. Omitted configuration leaves retention disabled. Enablement requires an explicitly configured, private operator root outside every configured workspace root. `--no-persist` suppresses retained traces. Coverage exceptions must be explicit in the event contract and acceptance tests.

### Status and diagnosis

Add `laew status --manifest PATH [--json] [--probe]` and `laew telemetry show RUN_ID [--json]` on [cli.py](../../laew/cli.py). Default status reads validated config, existing files and snapshots without creating stores, instantiating Workbench, or starting model/embedding work. Separate optional reachability checks on configured, approved endpoints, under an overall 3-second deadline and bounded per-check timeout. Use provider metadata/health and Chroma heartbeat only where supported; refuse endpoint redirects and external probes by default. Probes indicate reachability and readiness of the tested interface. Freshness is a separate cached sync timestamp/state with age and stale/unknown result based on policy. No credentials are loaded for a metadata probe unless its approved interface specifically needs them. No index refresh or DB migration.

`status` v1 returns `observed_at`, `overall`, and stable `checks[]` with component, state, reason code, measured time/age where available and `source=config|filesystem|cache|probe`. Check manifest and canonical roots, session and existing DB accessibility, provider configuration/reachability, Chroma reachability and RAG staleness, telemetry health, disk free space, and last verified backup/drill age. Keep optional unconfigured components `disabled`, unprobed dependencies `unknown`, errors classified and sanitised, and unavailable required dependencies `unavailable`. Exit 0 when all required checks positively pass, 1 for degraded/required unknown, 2 for invalid config or an unavailable required dependency. Include portable process elapsed time, CPU time and free disk bytes where measured. Remote GPU/RSS metrics stay unknown unless a future operator-approved adapter supplies a reliable measurement. Keep Workbench display semantics compatible. Reuse only pure helpers from its current status path.

### Capture, integrity and recovery contract

1. **Inventory and fence.** Propose `laew backup plan/create/verify/list/prune` and `laew restore --verify-only|--target EMPTY_DIR` against an explicit profile. Inventory canonical paths and host IDs, permissions, mounts, disk requirements, excluded files and eligible classification before capture. Require an exclusive backup operation lock and a maintenance fence for LAEW writers. For v1 use stopped instances and local ownership, with participating launchers honoring a shared/exclusive OS lock around their full writer lifetimes. Document a pre-upgrade operator barrier for programs that lack this lock. Stop/drain CLI, console, Workbench and all workers, attribution jobs, RAG sync/migration and external scripts that can mutate captured data. Confirm process exit and prevent automatic restart during capture. Closing a worker with a timed join is insufficient. Pause Obsidian/editor sync and filesystem/transfer jobs or use an approved read-only snapshot. Fail closed when any writer is uncertain. Use a host-specific profile and lock, not collection locks as distributed coordination. If authoritative state spans hosts, stop/fence all writers and record a shared cut identifier and each host's source manifest before any resumes. Defer unattended multi-host operation until ownership, acknowledgments and an isolated drill are approved.
2. **Capture a consistent cut.** Use individually validated stable session files and authoritative vault paths. Snapshot SQLite with `Connection.backup` over opened existing DBs and bound lock/busy waits. Compare file identity/inventory before and after read, with a final tree check to detect external changes. Two stable scans cannot prove exclusion of all external writers. Validate recoverability of curation publication states, including approved row before file creation, file present before applied marking, and index pending after file creation. Compare proposal/target hashes and versions. Preserve pending states for dry-run reconciliation, treat ambiguities as requiring operator decision, and never blindly replay publish or extract side effects. WAL file copying cannot substitute for a database backup and separately captured WAL databases cannot establish the cross-store cut. [Python SQLite backup API](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup) · [SQLite WAL documentation](https://sqlite.org/wal.html)
3. **Publish sealed archives.** Use stdlib ZIP64 or an equivalent reviewed streaming container, staged on the destination filesystem with restrictive owner ACL. Inventory includes schema, UTC times, logical roots, host/cut ID, code/config fingerprints, per-file relative path, size, SHA-256 and required metadata, version constraints and exclusions. No credential-bearing paths. Flush staged archive, read it back with size/hash/CRC checks and publish by same-filesystem rename under lock. Write a verified receipt last; readers revalidate candidates and accept only complete committed sets. On POSIX sync parent directory metadata. On Windows use tested same-volume publication and platform-appropriate durable flush where supported. State tested filesystem assumptions explicitly. Inject interruption before and after publish, including before receipt. No publication guarantee for untested filesystems, network shares or sudden loss of the sole backup medium. A checksum detects corruption; use trusted ACL and approved encrypted destination/transfer for authenticity and confidentiality. Treat imported archives as untrusted even if checksums match.
4. **Schedule and retain.** Start with stand-alone full archives, proposed nightly captures in an operator-approved maintenance window, plus a manual pre-change run. Use Windows Task Scheduler on the owning Windows host or systemd timer on the owning Debian host. Skip overlapping runs, fail on unconfirmed quiescence, retain prior good archive on failure, and report missed/stale backups clearly. Rotation proposal is seven daily, four weekly and a pinned last-known-good archive. Verify a fresh archive before pruning any prior archive. Expose a prune plan and require explicit eligibility rules. If full capture exceeds the agreed window/storage budget, evaluate file-level content-addressed incrementals with complete manifests, bounded to a weekly full baseline. Always take a full SQLite snapshot before file-level deduplication. Refcount/reachability checks plus restore of a retained base/incremental set would be required before pruning. No incremental support is needed for roadmap acceptance.
5. **Verify and restore in isolation.** Validate archive size/count limits, integer sizes, unique canonical member names, case collisions and logical roots before extraction. Reject traversal, absolute paths, device names, symlinks, junctions, ADS and source/target aliases. Use exclusive fresh targets and verify bytes again after extraction. Keep workers disabled, provider credentials absent and network fenced to enumerated fixture endpoints. Validate all sessions, DB records/FKs/job references, settings and links. Build a new runtime against isolated project/vault roots with worker and model fakes. Verify restart/resume, prior source links and project/global RAG scope, memory recall and publish reconciliation dry run. Existing project ID and collection identity depend on the canonical absolute path. A relocated workspace must use an explicit, validated logical project-ID mapping (or an isolated path-equivalent host) before resuming histories. Same for memory namespace derivation from a DB override. Refuse ambiguous remaps. Compare scoped ingestion manifests, record IDs where path-stable, citations and collection/embedding identity. With approved real rebuild future run, count sources/chunks and estimate time/GPU before authorization. Do not regenerate embeddings merely to check backups.
6. **Treat live cutover as a separate operation.** Keep current state intact and offline while validating isolated state. Document a reversible operator cutover with old roots/config retained, a durable journal of proposed changes, and a restart gate. Mixed generations are invalid. On error, stop instances and re-select the last verified consistent set. Activation, restore over live data and enabling jobs require explicit approval. Failed or interrupted staging stays unpublished, classified and removable only inside the known staging root.

Proposed **RPO ≤24 hours** for enabled authoritative data when nightly capture works. A missed window moves status to degraded and increases observed RPO. Proposed **RTO ≤2 hours** to resume sessions/vault using a verified archive and preinstalled compatible runtime on one host. Retrieval recovery after rebuilding embeddings and distributed deployment have separate measured RTO, currently unknown. Make timing and capacity acceptance conditional on a representative, authorized drill. Capture needs at least one staged source copy plus one archive and verify/restore scratch space on the appropriately sized volumes. Estimate retained storage conservatively as the effective count of full archives times measured archive size. No GPU required for fixture drills.

Proposed capture interface uses `laew backup plan --profile PROFILE` to produce an inventory and exclusions, `laew backup create --profile PROFILE` to capture under the fence, and `laew backup verify --profile PROFILE --id ID` for independent read-back. `laew restore --profile PROFILE --id ID --verify-only` performs verification without publishing a restore. `--target EMPTY_DIR` selects a fresh restore. A v1 receipt carries `backup_id`, `cut_id`, manifest and archive digests, `verified_at`, byte/member counts and profile/host identifiers. A status reader takes the last valid completed receipt as cached evidence and labels its age. A deeper verify checks the archive and recomputes digests. For optional transfer to another host with no authoritative writer, stage an immutable copy there, reverify and publish a local receipt. A transfer failure cannot invalidate the source generation. Multiple authoritative hosts need a durable coordinator receipt linking the completed host receipts in the same cut.

### Decisions and trade-offs

| Choice and alternatives | Selection, dependency and cost | Security and limits |
|---|---|---|
| Local JSONL, shared rotating log, or external telemetry backend | Per-run JSONL through stdlib. Reuses logging and avoids shared writer collisions. Lookup and caps need local indexes/locks only where benchmarks justify them | Private scope and allowlist. Flushed root events help crash diagnosis; tail loss is possible |
| Adapter-based instrumentation or provider-wide monkeypatch/decorator | Explicit hooks at run owners, existing executor and owned provider paths. Requires a coverage inventory and parity tests | Preserve callbacks, signatures and routing. Avoid logging raw values from Workbench or provider payloads |
| Active health loop or bounded operator status | Read-only default plus explicit bounded probes. No new operational service | Cached evidence can be stale; validate endpoint identity and suppress details that expose credentials or topology |
| Live copies, OS snapshots, or offline consistency boundary | Offline authoritative cut with SQLite API. Requires approved downtime and writer ownership. Host snapshots can later substitute for the file capture layer after proof | Fail on uncontrolled writers and avoid assuming host-local locks fence remote clients |
| Archive Chroma on every run or rebuild derived indexes | Rebuild from versioned canonical inputs. Requires compatible tools and pinned identity to reproduce; recovery incurs indexing time | Protect raw texts/vectors from extra replication.
