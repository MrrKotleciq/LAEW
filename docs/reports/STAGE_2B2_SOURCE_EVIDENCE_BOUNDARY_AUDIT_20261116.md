established 1,000-token **per-scope** accounting. It preserves all six frozen
minimum requirements, checksum caution, summary wait/catch-up qualification and
the safeguard against removing a required ancestor. It uses explicit source

This is a constructive, post-result, agent-reviewed feasibility witness for the
original configuration/file-inventory question, not independent domain validation,

The cost is **1,008 tokens including the existing global wrapper**, which the

If 1,000 is instead imposed on the entire enclosing section, this fixture does
not fit. No accounting convention or production renderer was changed.

backup execution flow. Its registered minimum fits in 199 tokens with the

costs 332 tokens but is absent in every frozen B/C K10/K20 pool. It is a

S04's reported C closure failures are **formal-heading availability artifacts**.
The retained body already names `max_wal_size` and states automatic-checkpoint,

# S12 — explain the apparent conflict without relabeling

The original question is a PostgreSQL 11 non-exclusive physical-backup script
being ported to 17, asking which start/stop API, session rules and returned
metadata preservation to use. The frozen criterion checks the target API names,
initiating connection lifetime/abort condition, and exact returned-file mapping.

| Closure | Finding |
|---|---|
| Target-17 API identity | Necessary; old `pg_start_backup` text cannot substitute. Two endpoint snapshots do not establish the exact release where an API changed. |
| Initiating connection retained through backup, or abort | Necessary. This complete sentence is already an admitted frozen proof. |
| Same connection for stop | A genuine invocation dependency; required when supplying script/invocation guidance. Whether name-only evidence suffices for the original wording requires review. |
| `backup_label`, nonempty `tablespace_map`, backup-root placement, byte-for-byte preservation and binary-mode caveat | Necessary; retain the full returned-metadata paragraph, including its field-count antecedent. |
| Start privileges/arguments, WAL-archiving precondition | Required for executable invocation/full procedure; unnecessarily broad as a universal closure of every API-name or session sentence. |
| Primary/standby switch behavior | Required when claiming switch behavior or explaining archive completion; not necessary merely to identify a function or returned metadata. |
| `wait_for_archive`, standby `archive_mode=always`, timeout/validity caveat | Necessary for archive-wait/completion/timeout guidance; unknown role cannot be silently treated as primary. |
| File copy, sequential success checks and completion step | Required in a runnable backup flow. Never splice source steps 2 and 4 into a claimed complete procedure while omitting step 3 and completion. |
| Fast checkpoint/I/O choice | Conditional on advising that option; optional for a name/session/metadata comparison. |

The 199-token registered-minimum fixture is mechanically complete under unchanged
v2.1 and candidate-contained for B/en and B/de at both K. It is evidence for a
contract, not a runnable script. The stronger same-connection invocation contract
costs 332 tokens with existing grouped citations, but **none of the twelve frozen
pools contains all its required ranges**. Quoting source code does not certify a
full procedure; the compact fixture explicitly states this.

In B/K10-en, exact old-closure gaps include chars 23565:23934 (archiving/start
invocation scope) and 25317:25649 (same-connection stop and part of WAL-switch
scope). Those are real absent ranges, not absent registered API/session/metadata
proofs. The historical contradiction came from asking two different completeness
questions. This audit proposes narrower claim-level closures, records the genuine
missing invocation scope separately, and changes no original score or annotation.

# S04 — identify the actual dependency

The original question is: “PostgreSQL 17 has max_wal_size set to 1 GB, but
archiving is failing and pg_wal grows beyond it. Has a hard limit been violated,
and what does this setting actually promise?” This is not a backup API question.

The source proof at chars **24307:24560** names `max_wal_size`, says it concerns
automatic checkpoints and is a soft limit, and explicitly includes failing
archiving among exceptions. The source paragraph's recovery-time warning is at
24650:24734. The explanation fixture costs 121 tokens; including that conditional
warning costs 155. Both are available in every B/C K10/K20 language pool.

The old closure instead demanded chars 24192:24826, including the separate formal
parameter header. In C/K10-en the actual missing cell is 24192:24307, **only that
header**; the parameter identity is already present in the retained body. The
same heading issue explains the reported C/K10-pl and C/K20-en rejections. Thus
these failures are overconstraint artifacts, not evidence of missing technical
dependencies or a broken soft-limit explanation. This does not imply that a
heading is optional for an identity-free number or “this parameter” elsewhere.

# Citation and serialization accounting

All figures use `ceil(joined_characters / 4)`; attribution, separators and notices
are included. Source attribution is full identity/revision/hash plus exact
zero-based, half-open Unicode source offsets. The PostgreSQL-17 WAL source is
bound to its REL_17_STABLE commit; the archiving page is a distinct REL_17_10
snapshot. Both complete identities remain visible and are not collapsed to an
ambiguous generic “PostgreSQL 17” citation.

| Fixed witness | Historical whole | Remove tags/backlinks only, same bodies | Grouped source union | Reviewed sentence/definition evidence |
|---|---:|---:|---:|---:|
| P03-en B/K10 | 3699 | 1874 | 1324 | 1039; 991 with compact separators + notice |
| P03-en C/K20 | 4768 | 2568 | 1468 | 1039; 991 with compact separators + notice |
| S12-en B/K10 | 889 | 538 | 456 | 199 for name/session/metadata scope |
| S04-en B/K10 | 645 | 271 | 265 | 122 for explanation scope |

These stages change different things. P03 B/K10's 5,600 original body characters
contain **792 characters of same-source overlap** and no synthetic payload
difference. Its source-union body has 4,808 characters. The historical-to-grouped
9,501-character saving decomposes into 792 source-overlap characters plus 8,709
overhead characters. Tags/backlinks removal alone saves 7,301 characters with
the bodies unchanged; this is a separate control, not an additional saving to
add again. Under an otherwise fixed full-source-header schema, grouping headers
once per source saves 959 characters. Those controls must not be double-counted.

For C/K20, 1,353 characters are same-source overlap, 385 are synthetic/raw-payload
representation difference, and 11,462 are overhead difference. Not all of the
4,768→1,468 reduction is source-body extraction or citation grouping.

Compared with the *original minimum whole witness's source union*, the reviewed
P03 sentence fixture removes 1,789 characters and **adds 208 necessary source
characters from other already-retrieved candidates**. Its net body reduction is
1,581 characters. This is another reason not to describe all savings as simple
trimming of the original seven chunks. Full per-question accounting is external.

The compact P03 sentence fixture then saves 191 characters net: ten gap markers
shrink by 22 characters each, while the notice adds 29. This is **48 estimated
tokens of serialization cost**, with body/citation identity/ranges unchanged.
The 991 result therefore depends on both reviewed boundaries and an explicit
serialization fixture; boundary changes alone cost 1,039 in the old format.

Grouping preserves traceability when every range remains assigned to the correct
source. It must not glue disjoint procedural steps together. Exact offsets and
visible separators make gaps mechanically detectable; whether a reader/model
respects them is a semantic/behavioral question. No answer generation was tested.
