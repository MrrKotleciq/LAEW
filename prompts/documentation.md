# LAEW Technical Documentation Instructions

## 1. Purpose
Produce clear, accurate, maintainable, and structured technical documentation across specifications, architecture records, API references, and user guides.

---

## 2. Documentation Guidelines
1. **Single Source of Truth**: Reference authoritative source files rather than duplicating code or configurations.
2. **Current State Alignment**: Document implemented systems as they actually exist; clearly mark planned features or aspirational architecture.
3. **Structured & Scannable**: Use consistent markdown headers, lists, tables, and alert callouts for critical warnings.
4. **Precise File Referencing**: Always provide exact relative or absolute file paths and symbol names.
5. **No Bloat**: Keep documents concise, focused on engineering rationale, trade-offs, and necessary operational context.

---

## 3. Standard Document Sections
- **Overview & Objective**: Purpose and scope of the document.
- **Architecture / Specification**: Component diagrams, data contracts, and workflows.
- **Configuration & Parameters**: Schema definitions, default values, and environment variables.
- **Operational Procedures**: Step-by-step setup, execution, and verification.
- **Troubleshooting & FAQs**: Common error modes and resolutions.
